# memory-metabolism

AIアシスタントのメモリが育ちすぎて答えが崩れるのを防ぐ、Claude向けスキル。「チェックは頻繁に、消すのは承認制でまとめて」を軸に、常駐メモリの棚卸し、シーン別ファイルへの分割、整理前後の訂正検証までを手順化してある。

## 何をするスキルか

長く使ったAIアシスタントは、だんだん賢くなるのではなく、だんだん矛盾するようになる。終わった案件、古い決定、訂正されたはずの事実がメモリに残り続け、新しい指示と同居するからだ。このスキルは、その「育ちすぎ」を代謝させる。

中身の大半は、判断に迷いやすいところを決まりで固定したもの。

- メモリの置き場を4層（常駐／シーン別／日次ログ／アーカイブ）に分け、置くもの・置かないものを表で決める
- 常駐に足す前に問う「3問」（毎回必要な前提か、実測値ではないか、既存の記述と矛盾しないか）
- 常駐サイズの目安を数値で持つ（合計30,000字まで健全圏、50,000字超は危険圏）
- 棚卸しは5ステップ（測る→候補を出す→分類する→承認を得る→適用して検証する）。候補を出す段階ではファイルを変更しない
- 過去に訂正された事実は「訂正台帳」に残して削除候補から外し、整理の前後で最低3問を再質問して、答えが崩れていないことを完了の条件にする

作者の運用では、常駐の合計が約65,000字（MEMORY.mdだけで47,451字・86項目）に達した時点で矛盾が目立ち始めた。整理後はMEMORY.mdを12,066字（超重要事項＋シーン別ファイルへの目次だけ）にし、詳細は9つのシーン別ファイルへ**要約せず全文のまま**移した。情報は減らしていない。毎回読む量だけを減らした。このスキルは、その運用をどの環境でも再現できるように整理し直したもの。

## 使い方

Claude CodeやClaudeのスキル対応環境で、`skills/memory-metabolism/SKILL.md`を読み込める場所に置く。テンプレート（`skills/memory-metabolism/templates/`）と設定の見本（`config.example.md`）は、SKILL.mdから参照されるので、フォルダごと置く。

### Claudeのチャット（claude.ai・デスクトップアプリ）で使う

設定の「機能」で「クラウドでコードを実行」と「外部ネットワークへの通信を許可」をオンにしてから、新しいチャットで次のように送る。

```
https://github.com/ai-jissen-lab/memory-metabolism のスキルを使えるようにして
```

うまくいかないときは、`skills/memory-metabolism`フォルダを丸ごとzipにして、「設定」の「Skills」からアップロードする。

### Claude Codeで使う

```
git clone https://github.com/ai-jissen-lab/memory-metabolism.git
cp -r memory-metabolism/skills/memory-metabolism ~/.claude/skills/
```

置いたあとは「メモリを棚卸しして」「最近、前に直した間違いを繰り返す」のように頼めば、スキルの説明文にある条件に合ったときにClaudeが自動で読み込む。

## 最初に使うとき

初めて棚卸しを頼むと、Claudeは始める前に、いまの既定値を見せて設定を一度だけ尋ねる。尋ねるのは常駐ファイル、置き場の構成、常駐の上限の目安、チェックの頻度、承認者の5つ。「このままでいい」と答えれば既定値で始める。決まった設定はスキルのフォルダに`config.md`として保存され、次からは尋ねない。質問を飛ばしたいなら、先に`config.example.md`を`config.md`という名前でコピーし、値を書き換えておけばいい。

## 着想

「メモリの育ちすぎがAIの自己矛盾を生む」「チェックは毎晩、消すのは承認制で週1」という着想は、テツメモ（@tetumemo）のメモリ運用メモから得た。本スキルはその考え方に、シーン別ファイルへの全文移設、訂正台帳による整理前後の検証、サイズの数値目安を加えて、実装手順として整理し直したものである。詳しくはNOTES.mdにまとめた。
